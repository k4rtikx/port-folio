Write Together: Real-Time Collaborative EditorLive

A browser-based editor where multiple users work in shared document rooms and see each other’s changes in real time over WebSockets, with shareable room links and a live online-user count.

Quill editor→WebSocket (Django Channels)→Redis cache→Broadcast to room+Background thread → PostgreSQL
PythonDjango ChannelsWebSocketsASGIRedisPostgreSQLQuill.jsRender
Live DemoGitHub
View Project Details

Features

  • Real-time collaborative editing with WebSocket synchronization
  • Shareable room links and a live online-user count
  • Redis caching with PostgreSQL persistence

Problem 1: character corruption and cursor jumping

The first version sent the entire document HTML on every keystroke, and receiving clients replaced their editor contents with innerHTML. Concurrent updates could overwrite edits and disrupt the cursor.

Fix: I changed the flow to send document changes instead of the full HTML, and added sender-channel filtering so an update is not echoed back to the client that made it. Result: fewer unnecessary full-document replacements, and the specific overwrite and cursor issues were addressed.

Problem 2: editing latency

Writing synchronously to a remote Neon PostgreSQL database before broadcasting added a delay I observed at roughly 200–400 ms.

Fix: cache the update in Redis, broadcast immediately, and persist to PostgreSQL in a background thread. On the Redis path I observed about 1 ms under the conditions I tested.

These figures are observations from my own testing, not formal benchmarks. This is not a complete conflict-free editing algorithm.
